# 📡 NetScanner — اسکنر شبکهٔ داخلی با گزارش دقیق (بدون حدس)

ابزار اسکن شبکهٔ محلی که همهٔ دستگاه‌های موجود را پیدا می‌کند و برای هر دستگاه
**فقط اطلاعات واقعی** ارائه می‌دهد: هر داده، «منبع» و «سطح اطمینان» خودش را دارد و
هرگز مقدار حدسی/تقریبی جای اطلاعات واقعی گذاشته نمی‌شود (اگر چیزی پیدا نشود،
صریحاً «نامشخص» نوشته می‌شود).

- رابط وب فارسی (RTL) برای اسکن زنده + گزارش HTML مستقل + خروجی JSON/CSV
- فقط کتابخانهٔ استاندارد پایتون ۳ — **بدون هیچ وابستگی بیرونی**
- چندلایه: ARP خام، ICMP Echo/Timestamp، TCP SYN، TCP Connect، UDP، SSDP/UPnP،
  WS-Discovery/ONVIF، mDNS، NetBIOS، SNMP، IPP، RTSP، TLS، جدول ARP/NDP،
  اجاره‌های DHCP و اتصال‌های فعال سیستم

---

## ۱) نصب و اجرا

نیازی به نصب چیزی نیست (پایتون ۳.۸+ کافی است):

```bash
# اجرای رابط وب  (سپس در مرورگر: http://localhost:8000)
sudo python3 -m netscan --serve

# اسکن سریع شبکهٔ محلی با گزارش متنی
sudo python3 -m netscan

# اسکن یک شبکهٔ مشخص + ذخیرهٔ گزارش‌ها
sudo python3 -m netscan --target 192.168.1.0/24 --ports common \
     --html report.html --json result.json --csv result.csv

# همهٔ شبکه‌هایی که این دستگاه به آن‌ها وصل است
sudo python3 -m netscan --target all

# دانلود فهرست رسمی IEEE OUI (برای تشخیص دقیق‌تر سازندهٔ کارت شبکه)
sudo python3 -m netscan --update-oui
```

> **مهم:** با `sudo` (دسترسی root) اجرا کنید. در این حالت لایه‌های ARP/ICMP/TCP-SYN خام
> فعال می‌شوند؛ این‌ها قوی‌ترین روش‌های کشف‌اند و فایروال دستگاه‌ها نمی‌تواند آن‌ها را
> پنهان کند. بدون root، برنامه همچنان کار می‌کند و از TCP/UDP/ping و منابع غیرفعال
> استفاده می‌کند، ولی برخی دستگاه‌ها ممکن است دیده نشوند (برنامه این محدودیت را
> صریحاً در خروجی هشدار می‌دهد).

## ۲) گزینه‌های خط فرمان

| گزینه | توضیح |
|---|---|
| `--target` / `-t` | `192.168.1.0/24` یا `192.168.1.10` یا `192.168.1.10-60` یا `all` |
| `--interface` / `-i` | نام رابط شبکه (مثل `eth0`، `wlan0`) |
| `--ports` | `quick` (۱۰ پورت) / `common` (۱۵۰ پورت) / `full` (۱۰٬۰۰۰) / `all` (۶۵٬۵۳۵) |
| `--ports-plus` | پورت‌های سفارشی: `8080,9000-9010` |
| `--mode` | `auto` (همهٔ لایه‌ها) یا `fast` |
| `--snmp-community` | رشتهٔ community برای SNMP (پیش‌فرض `public`) |
| `--no-snmp` | غیرفعال‌کردن کاوش SNMP |
| `--timeout`, `--workers`, `--host-workers`, `--max-hosts` | تنظیم سرعت و دامنهٔ اسکن |
| `--json`, `--html`, `--csv` | ذخیرهٔ خروجی |
| `--serve --host --port` | اجرای رابط وب |
| `--list-interfaces` | نمایش رابط‌های شبکه و خروج |
| `--update-oui` | دانلود `oui.csv` رسمی IEEE در پوشهٔ `data/` |

## ۳) رابط وب

```bash
sudo python3 -m netscan --serve --port 8000
```

سپس `http://localhost:8000` را باز کنید:

1. گسترهٔ هدف (پیشنهاد خودکار از رابط‌های شبکه) را انتخاب کنید.
2. «شروع اسکن» را بزنید؛ پیشرفت زنده، گزارش رویدادها و جدول دستگاه‌ها به‌روز می‌شود.
3. روی هر ردیف کلیک کنید تا **جدول کامل اطلاعات + منبع هر مورد** را ببینید.
4. خروجی: `JSON`، `CSV` و **گزارش HTML مستقل** (یک فایل خودبسنده برای بایگانی/ارسال).

## ۴) برنامه چطور «دقیق» کار می‌کند؟

هر ادعا در خروجی یکی از این سه دسته است و در رابط کاربری با برچسب مشخص شده است:

| برچسب | معنی | مثال |
|---|---|---|
| **قطعی** | از پاسخ واقعی خود دستگاه خوانده شده | هدر `Server`، بنر SSH، مدل چاپگر در IPP، `sysDescr` در SNMP، گواهی TLS، پاسخ ARP/ICMP/TCP |
| **ثبت‌شده** | از منابع رسمی/سیستم | پیشوند OUI در فهرست رسمی IEEE، فایل اجارهٔ DHCP، جدول ARP/NDP هسته |
| **استنتاجی** | غیرقطعی و همیشه جدا نمایش داده می‌شود | «به احتمال زیاد دستگاه اپل» با ذکر دلیل «سازندهٔ OUI: Apple» |

### لایه‌های کشف میزبان

| لایه | چه چیزی را ثابت می‌کند |
|---|---|
| ARP خام (`AF_PACKET`) | دستگاه در شبکهٔ محلی زنده است + **MAC واقعی** (قوی‌ترین روش) |
| ICMP Echo و Timestamp | دستگاه در لایهٔ ۳ پاسخ می‌دهد |
| ICMP port-unreachable | پیام خطا = میزبان قطعاً زنده است (حتی اگر همهٔ پورت‌ها بسته باشند) |
| TCP SYN (خام) | پاسخ SYN/ACK یا RST = میزبان زنده + وضعیت پورت |
| TCP Connect | پورت باز (شاهد قطعی) |
| UDP (mDNS/SSDP/NBNS/SNMP) | پاسخ سرویس یا ICMP غیرقابل‌دسترس |
| `ping` سیستم | لایهٔ پشتیبان در همهٔ سیستم‌عامل‌ها |
| جدول ARP/NDP، DHCP، اتصال‌های فعال | دستگاه‌هایی که با این سیستم تبادل داشته‌اند |

### پروتکل‌های هویت‌سنجی (روی هر دستگاه زنده)

- **UPnP/SSDP**: `friendlyName`، `manufacturer`، `modelName`، `serialNumber`، سرویس‌ها
- **WS-Discovery/ONVIF**: نوع دستگاه و Scopes (مدل و سازندهٔ دوربین‌های IP)
- **mDNS (Bonjour)**: نام میزبان واقعی + سرویس‌های اعلام‌شده (`_printer._tcp` و…)
- **NetBIOS**: نام دستگاه، گروه کاری/دامنه، MAC
- **SNMP**: `sysDescr`، `sysName`، `sysLocation`، شمارهٔ سریال
- **IPP**: مدل دقیق چاپگر، نام، محل، ID دستگاه، UUID
- **RTSP**: نام/نسخهٔ دقیق دوربین‌ها و ضبط‌کننده‌ها
- **TLS**: CN، سازمان، **SAN**، تاریخ انقضا، نسخهٔ TLS و رمزنگاری
- **HTTP/HTTPS**: هدر `Server`، `X-Powered-By`، عنوان صفحه، متا تگ‌ها، درخواست احراز هویت
- **بنر خام TCP**: SSH، SMTP، FTP، Telnet
- **DHCP leases**: نام ثبت‌شده، MAC، و زمان اجاره (dnsmasq / ISC dhcpd / Kea)

### محدودیت‌های واقعی (صادقانه)

- کاوش فعال فقط روی محدودهٔ آدرس‌های خصوصی و محلی انجام می‌شود
  (`10/8`، `172.16/12`، `192.168/16`، `169.254/16`، `100.64/10`، `127/8`).
- دستگاه‌های کاملاً خاموش یا دستگاه‌هایی که همهٔ پاسخ‌ها را می‌بندند، فقط اگر
  در جدول ARP/اجارهٔ DHCP موجود باشند دیده می‌شوند (و آن هم با ذکر منبع).
- هویت‌سنجی SNMP روی رشتهٔ community پیش‌فرض `public` انجام می‌شود؛ اگر دستگاه
  رشتهٔ دیگری داشته باشد، مقدار آن ثبت نمی‌شود (برنامه حدس نمی‌زند و حملهٔ
  culture-brute-force انجام نمی‌دهد).
- پیشوندهای OUI که آزاد/تصادفی‌اند (MAC دستگاه‌های مدرن با Random MAC) هیچ‌وقت
  نام سازنده نمی‌گیرند؛ به‌جایش «MAC تصادفی» علامت می‌خورد.
- اسکن IPv6 فعال نیست؛ اما همسایه‌های IPv6 از جدول هسته خوانده و با تطبیق MAC
  واقعی به همان دستگاه نسبت داده می‌شوند.

## ۵) ساختار پروژه

```
netscan/
├── __main__.py     خط فرمان (اسکن، گزارش‌ها، سرور وب، به‌روزرسانی OUI)
├── server.py       سرور وب + API با کتابخانهٔ استاندارد (SSE برای رخدادهای زنده)
├── core.py         موتور اسکن: توالی فازها، کاوش عمیق، ساخت جدول واقعیت‌ها
├── discovery.py    کشف میزبان: ARP/ICMP/SYN خام، TCP/UDP، SSDP، WS-Discovery، mDNS، NetBIOS، DHCP
├── probe.py        کاوش سرویس: HTTP/TLS/SSH/RTSP/IPP/SNMP/UPnP، خواندن فایل توصیف UPnP
├── parsers.py      تجزیه‌گرهای باینری: X.509، IPP، DNS/mDNS، SNMP(BER)، اجاره‌های DHCP
├── netinfo.py      رابط‌ها و گسترهٔ آدرس‌ها از خود سیستم‌عامل (Linux/macOS/Windows)
├── oui.py          جست‌وجوی سازنده در فهرست رسمی IEEE (با چند مسیر پشتیبان)
├── oui_data.py     واژه‌نامهٔ کوچک داخلی (فقط آخرین راه‌حل، با ذکر منبع)
├── report.py       گزارش HTML مستقل و خودبسنده
└── static/         رابط کاربری وب (index.html + app.js + style.css)
tests/test_integration.py   تست یکپارچه با سرورهای ساختگی HTTP/HTTPS
```

## ۶) API سرور وب

| مسیر | کار |
|---|---|
| `GET /api/context` | رابط‌ها، دروازه، توانایی‌های اسکن، وضعیت فهرست OUI |
| `POST /api/scan` | شروع اسکن (JSON) → `{"scan_id": "..."}` |
| `GET /api/stream/<id>` | رویدادهای زنده (SSE): فازها، لاگ، دستگاه‌ها، پایان |
| `POST /api/stop/<id>` | توقف اسکن |
| `GET /api/result/<id>` | نتیجهٔ کامل JSON |
| `GET /api/export/<id>.<json\|csv\|html>` | خروجی برای دانلود |
| `POST /api/oui/update` | دانلود فهرست رسمی IEEE |

بدنهٔ `POST /api/scan`:

```json
{
  "target": "192.168.1.0/24",
  "interface": "eth0",
  "ports": "common",
  "extra_ports": "8080,9000-9010",
  "mode": "auto",
  "snmp": true,
  "snmp_community": "public",
  "tcp_timeout": 0.7,
  "workers": 256,
  "host_workers": 16,
  "max_hosts": 4096
}
```

## ۷) تست

```bash
python3 tests/test_integration.py
```

این تست دو سرور ساختگی HTTP و HTTPS روی localhost بالا می‌آورد و بررسی می‌کند که
موتور اسکن، هدر واقعی `Server`، عنوان صفحه و CN گواهی TLS را درست استخراج و با
ذکر منبع گزارش کند.
